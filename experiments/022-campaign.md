# 022 — 複数行ソースとバイナリの取り込み

2026-11-04 JST。021のキャンペーンを引き継ぎ、[ステージ指示](022-campaign-prompt.txt)に沿ってファイル上限を8 KiB、名前付きファイル数を16に広げた。旧形式をゲスト自身が移行し、`recv NAME N` が指定バイト数をUARTから読み取る。

初期候補では旧ディスクの起動、次の候補では取り込みまたは再起動後の読取りが失敗した。通信エラー後の再開と、既存のプロセス入出力の回帰を伝えるため、続行指示は計2回。最終版では旧ファイル、改行とタブを含むCソース、全256種のバイトを含む8 KiBのファイル、空ファイルの内容が再起動後に一致した。サイズ超過は元のファイルを維持した。プロセス入出力、Cの関数呼び出し、アセンブラの自己ホスト、ブラウザも観測側の回帰検証を通った。

[最終イメージ](022-campaign.hex)は、ゲストがディスクに保存した二つのバイナリ断片の連結結果とも一致した。ゲスト内で組み立てた [移行コード](022-FsBoot.s)、[受信コード](022-FsRecv.s)、[接続コード](022-FsFix.s) と [引き継ぎメモ](022-handoff.txt) を保存した。

再現は `python3 verify_source_import.py experiments/022-campaign.hex`。現在のCコンパイラが認識する空白はスペースなので、取り込んだ複数行ソースのコンパイルには字句解析の拡張が必要。
