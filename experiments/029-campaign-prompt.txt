Add an argv execution entry to the stage-028 guest shell, for future C and small CLI programs. Keep the existing run N command and compiler ABI. Use the guest assembler to build new code where practical. All 16 disk slots are occupied. Preserve all file bytes and metadata. If borrowing a slot, restore it before every reboot. The observer will independently compare the disk with its pre-stage snapshot.

New command: exec PROGRAM [ARG ...]. It runs the already loaded executable, using PROGRAM as argv[0] and splitting remaining nonempty tokens on spaces. No file lookup, quotation, tab support, or environment variables are required. Support at least eight tokens total, preserving spelling and order, with a documented bound. Require at least PROGRAM and reject too many tokens without executing. The standard old shell line limit is acceptable.

For the loaded AArch64 entry, pass x0=existing putc callback, w1=argc, x2=argv (64-bit pointers to null-terminated strings, followed by a null pointer). The vector and strings must remain valid throughout the call. The executable returns its exit status in w0 under the existing preservation convention, and exec prints the same exit format as run. It must be possible to call the putc callback and use argv afterward. Keep the normal stack aligned and preserve shell, disk, process, build and browser operation. Do not change run N or its semantics.

Demonstrate a guest-assembled application that uses the new ABI to print the arguments including argv[0] and returns a computed value or argc. Execute the exact same program with several argument vectors, including one and at least eight arguments, and then exercise legacy run N. Verify malformed exec input is rejected without running the program. Record the precise ABI, limits, integration offsets, source and reproduction steps, and stop the VM.
