# 037 — 外部から取得したソースをゲスト内でビルド

2026-11-04 JST。[ステージ指示](037-campaign-prompt.txt)に沿って、ゲストのシェルに `fetch PATH NAME` を追加した。ゲストのネットワークは実験用の専用Ethernetリンクに接続する。`GET /echo.c` を受けたホスト側の取得口は、固定のsbase 0.1アーカイブをHTTPSで取得し、アーカイブと `echo.c` のSHA-256を照合して421バイトをゲストへ返す。`/hello` はローカルの起動確認用で、対象外のパスはローカルで404を返す。[公式配布アーカイブ](https://dl.suckless.org/sbase/sbase-0.1.tar.gz)

観測側は取得元ソースが入っていない新規ディスクを起動し、ランダムな名前を保存先に指定した。PCAPのGETとHTTP 200応答、FINへのACK、取得口のHTTPS記録を照合した。ゲストが保存した内容は元の421バイトと一致し、対象外パスへの要求が404で拒否された後も、ネットワークなしで再起動した後も一致した。別の満杯のディスクでは、名前が一致するファイルだけを更新し、残り23ファイルを維持できた。

オフラインで、取得したファイルを[段階036の変換器](036-adapter.c)の入力に使った。ゲストが出力した保存コマンドをシリアルでそのまま返し、変換されたCをゲスト内でビルドした。生成した `echo` の出力と終了コードは、同じ上流版のホストビルドと6パターンで一致した。

途中候補では保存先を変えるとファイル名が切れ、別のファイルを書き換えた。観測結果を渡した続行指示1回でPiが修正した。最終カーネルで、キーボードからのパス入力、HTMLリンク移動、引数渡し、プロセス入出力、ディスク移行、Cコンパイラの自己ホストとCLIの回帰検証も通った。キャンペーンで変更したのは、取得したソース、再生成した移植版、ファイル保存処理のアセンブリを置いた3枠だけ。VMを停止した。

再現は以下。比較用のホストバイナリの作り方は[段階036の記録](036-campaign.md)を参照。

```sh
python3 verify_external_source.py experiments/037-campaign.hex experiments/032-seed.s \
  experiments/034-compiler.c experiments/035-compiler.c experiments/036-adapter.c \
  fixtures/sbase-0.1/echo.c /path/to/echo-reference
```
